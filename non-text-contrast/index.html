What 3:1 actually covers

WCAG 2.1 Success Criterion 1.4.11 (Non-text Contrast) requires a 3:1 ratio between a UI component or meaningful graphic and its adjacent colors. That covers four things: the visible boundary of controls (input borders, button outlines), meaningful icons and graphics (a chart line, a status icon, a diagram part), the state of a control (a checked checkbox, a selected tab), and the focus indicator. What it does not cover: text (that is 1.4.3, 4.5:1), purely decorative graphics, logos, and inactive or disabled components — those are explicitly exempt.

The focus-indicator trap: a ring has two neighbors

A focus ring must reach 3:1 against both adjacent colors — the control it surrounds and the page behind it. Checking only one side is the most common way a "passing" focus indicator ships broken. The classic failure is a blue ring on a blue button:

Focus ring vs…RatioVerdictWhat it means

#2563EB ring vs #1D4ED8 button1.30:1FailSame ring, same button family — invisible where it meets the control.
#93C5FD ring vs #2563EB button2.87:1FailA light ring on a blue button still falls short of 3:1.
#FFFFFF ring vs #2563EB button5.17:1PassA white ring on the blue button passes — pair it with a dark outer ring for the page side.
#2563EB ring vs #EFF6FF card4.75:1PassEven on a pale blue card the ring holds up.

The robust fix is a double ring: a white inner ring plus a dark outer ring (or the reverse). One of the two always contrasts with whatever sits on either side. WCAG 2.2 additionally asks the indicator to cover an area at least as large as a 2px perimeter of the component — this tool checks color only, so keep the ring thick enough as well as contrasting enough.

How to fix a failing component

  1. Go one shade darker (or lighter on dark). The fix is almost always a single step in your scale: gray-400 → gray-500 (2.54 → 4.83), slate-300 → slate-400 still fails (1.48 → 2.56), so for borders go two steps: slate-300 → slate-500 (1.48 → 4.76).
  2. Check the real adjacent color. A border that passes on white can fail on a tinted card — run the check with the card color, not the page color.
  3. For focus rings, use a double ring. White + dark, so the ring passes against both the control and the page no matter their colors.
  4. Do not rely on "it looks fine". #9CA3AF and #94A3B8 both look like perfectly readable grays on white; both measure 2.5:1 and fail. The number is the test.

How the math works

Same WCAG 2.1 ratio as the text checker: relative luminance from linearized sRGB (weights 0.2126 red, 0.7152 green, 0.0722 blue), then (L1 + 0.05) / (L2 + 0.05). Only the threshold changes — 3:1 instead of 4.5:1 — and the threshold is inclusive: exactly 3.00:1 passes. No uploads, no tracking: it all runs in your browser.

FAQ

Is 3:1 the rule for text too?

No. Text needs 4.5:1 for normal text and 3:1 for large text (WCAG 1.4.3). The 3:1 rule on this page is WCAG 1.4.11, which covers non-text elements only: icons, UI component borders, focus indicators, and meaningful graphics. A gray that passes here (for example #767676 at 4.54:1) still barely passes for text — check text with the contrast checker.

Do disabled controls need 3:1 contrast?

No. WCAG 1.4.11 explicitly exempts inactive user interface components — a disabled button or a grayed-out control does not need to meet 3:1. The exemption only applies while the control is genuinely disabled, not to controls that merely look subdued.

Does my logo need 3:1 contrast?

No. Logos and purely decorative graphics are exempt from 1.4.11. The rule applies to graphics that carry meaning — a chart line, a status icon, a diagram part — and to the visible boundaries of controls that users must find and operate.

What counts as the adjacent color for a border or icon?

The color directly next to the element: for an input border it is usually the page or card background behind the field; for an icon it is the fill of the button or surface it sits on. A focus indicator is special — it has two neighbors, the control and the page — and it must reach 3:1 against both.

My icon passes 3:1 but it sits inside a button — what do I check?

Both layers. Check the icon against the button's fill, and check the button's border (or the button's fill, if the button has no border) against the page background. Each boundary needs its own 3:1 — a passing icon on a button that melts into the page still fails.

Is my color data uploaded anywhere?

No. Everything runs locally in your browser; no colors, no analytics, no tracking.
