The two rules of WCAG 2.4.13

Focus Appearance (WCAG 2.2, level AA) has a color rule and an area rule, and a ring must pass both:

  1. Color — 3:1 against adjacent colors. The indicator must reach 3:1 against every color it touches. A focus ring touches two: the component it surrounds and the page behind it. Checking only one side is the most common way a "passing" ring ships broken.
  2. Area — at least a 2 px perimeter. The indicator must cover an area at least as large as a 2 CSS pixel thick band around the component. For a W × H component that is 4(W+H) + 16 px². A 2 px outline lands exactly on that number; a 1 px outline always falls short, however large the component.

Note the threshold is inclusive: exactly 3.00:1 passes, and exactly the required area passes. This tool checks color only against the two colors you enter and area only for a rectangular component with the ring hugging it (outline-offset 0 — the conservative case; an offset ring covers more area, not less).

The area rule, in numbers

Required area = 4(W+H) + 16 px². A 2 px outline always lands exactly on it; a 1 px outline always falls short; 3 px clears it with room to spare. The thickness rule is really an "at least 2 px" rule, stated as an area so non-rectangular indicators can be judged the same way.

How to fix a failing focus ring

  1. Use a double ring. A white inner ring plus a dark outer ring (or the reverse) — one of the two always contrasts with whatever sits on either side. It is the only fix that works no matter what the button and page colors are.
  2. Go one shade darker on light pages, one shade lighter on dark pages. #60A5FA → #2563EB on white (2.54 → 5.17); #2563EB → #60A5FA on dark (2.84 → 5.77 against a dark button).
  3. Make it at least 2 px thick. The browser default :focus-visible outline is usually 2 px — if your design system thins it to 1 px for looks, it fails the area rule even with a perfect color.
  4. Never remove the outline without a replacement. outline: none with no custom indicator is not a style choice; it removes the only way keyboard users can see where they are. If you restyle focus, replace it with something that passes this check.
  5. Check the real adjacent colors. A ring that passes on the page can fail on a tinted card or a colored button — run the check with the component's actual fill, not an assumed white.

How the math works

Color: the standard WCAG 2.1 ratio — relative luminance from linearized sRGB (weights 0.2126 red, 0.7152 green, 0.0722 blue), then (L1 + 0.05) / (L2 + 0.05) — checked twice, once per neighbor, against the 3:1 line. Area: a t px outline around a W × H rectangle covers (W+2t)(H+2t) − W×H = 2t(W+H) + 4t² px²; the required area is that formula at t = 2. No uploads, no tracking: it all runs in your browser. For the 3:1 rule on icons and borders generally, see the non-text contrast checker; for link colors, the link text checker.

FAQ

Is this the same as WCAG 1.4.11 non-text contrast?

No. WCAG 2.1 Success Criterion 1.4.11 only asks for 3:1 against adjacent colors. WCAG 2.2 Success Criterion 2.4.13 Focus Appearance keeps the 3:1 rule and adds an area rule: the indicator must cover at least as much area as a 2 CSS pixel thick perimeter of the component. A ring can pass 1.4.11 on color and still fail 2.4.13 on thickness — check both with the non-text contrast checker if you only need the color side.

My browser already draws a focus outline — do I need to check it?

Yes. Browser defaults vary — usually a 2 px outline, but the color depends on the browser and operating system (often blue, sometimes black). And many sites remove the default with outline: none, which leaves keyboard users with no visible focus at all. Check the color your users actually see.

What if my focus ring is offset from the component?

An offset ring covers more area, not less, so the area rule gets easier — this tool assumes offset 0, the conservative case. The gap between component and ring is page-colored, so the ring still needs 3:1 against the page. Checking both neighbors, as this tool does, never hurts.

Does the ring need 3:1 against the text inside the button?

No. The focus indicator is only measured against its adjacent colors — the component fill and the page. Text contrast is a separate rule, WCAG 1.4.3 (4.5:1 for normal text), covered by the contrast checker.

What is Focus Not Obscured (WCAG 2.4.11)?

A separate WCAG 2.2 criterion: when a component receives keyboard focus, at least part of it must stay visible — a sticky header or overlay must not cover it entirely. It is not a color or area number, so no calculator can test it: tab through the page and look.

Is my color data uploaded anywhere?

No. Everything runs locally in your browser; no colors, no analytics, no tracking.
